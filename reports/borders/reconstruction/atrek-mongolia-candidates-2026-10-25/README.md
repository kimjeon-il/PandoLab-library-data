## Atrek의 독립적으로 가능한 계산 검증

전달된 JSON은 파싱됐고, 원본 제어점의 역쌍선형 계산으로 수정 72점 전부를 다시 계산했다.

- 제어점: 경도 53°51′~54°21′E, 위도 37°09′~37°29′N. 전달된 4000×3582 렌더 좌표계 그대로 사용; 앱 경계에 맞추거나 스냅하지 않았다.
- 재계산 좌표와 GeoJSON의 최대 차이: **7.105427357601002e-15°**. 이는 전달된 제어점과 좌표 사이의 수학적 일관성이며 독립적인 지도 정확도 검증이 아니다.
- 72점 수정선은 LineString으로 유효·자기교차 없음. 좌표는 유한하며 경위도 수치 범위 안이고, 참조 2점 선과 시작·끝점이 같다.
- 이전 16점 비교선과 수정 72점 선을 최대 0.5 렌더 px 간격, 14,710 표본으로 대조한 대칭 거리: **61.0 렌더 px**. 전달된 값과 같다. **1.544761699948418 CSS px** 값은 앱 조건을 재실행하지 않아 전달값으로만 보존했다.
- 습지 해칭 겹침·인쇄 공백의 불확실 구간 2개와 보간 설명을 그대로 보존했다. 원본 데이텀은 미상이며 WGS84 변환을 수행하지 않았다. 좌표가 GeoJSON에 있다는 사실만으로 EPSG:4326 정합을 확정하지 않는다.
- `metadata.old_trace_source_px`는 이전 선 비교용이다. 이를 수정선으로 사용하지 않았다. `new_1955` 명칭은 생산 적용일을 정하는 필드가 아니다.

위 검증은 **선형과 전달된 지오레퍼런싱의 내부 일관성**이다. PNG 실제 기호 판독·측지 데이텀·원래 정치 경계·역사적 정확성·양국 폴리곤 접합·인접국 위상은 검증하지 못했다. 원문 SHA-256과 검증 결과는 validation.json에 기록했다.
