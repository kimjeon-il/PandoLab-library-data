# Map Toolkit 자동 릴리스 완료 절차

- 날짜: 2026-10-30 (Asia/Seoul)
- 범위: Codex가 관련 로컬 개발을 완료할 때 기존 PRIVATE USER Map Toolkit의 집중 검증·소스 푸시·패키징·업데이트·원격 확인을 수행한다. 일반 저장/푸시 감시, 공개 배포, 새 훈련, 앱 main 통합은 제외한다.
- 기존 패키징 소유자는 유지하고 release-private-plugin.mjs에 준비/업로드 결과 기록/원격 archive 확인을 연결했다. 플러그인 계정 ID는 사용자 로컬 설정에만 두며 소스·보고서에 자격 증명을 넣지 않는다.

## 판단 기록

- Ruling: 구현용 임시 워크트리/저장소를 만들지 않고 기존 work/ui를 사용한다. 아이콘 등 기존 WIP와 원격의 다른 변경을 덮어쓰지 않기 위해 작업 범위만 커밋하고 필요한 경우 Git tree에서 원격과 통합한다. 원격에 새 미검증 충돌이 있으면 임의 한쪽 선택 대신 중단한다.
- Ruling: 자동 갱신은 Codex 완료 절차의 일부다. Node 프로그램이 계정 토큰을 가져가거나 비공개 업로드 API를 흉내 내지 않는다. 인증된 Plugin Creator 호출은 Codex가 맡고, 로컬 실행기는 검증 기록·정확한 업로드 인자·원격 확인을 소유한다.
- Ruling: 검증은 커밋 후, 소스 푸시 전에도 가능하다. 패키징/업로드 준비에는 origin/work/ui에 포함된 커밋이 필요하다. Git의 텍스트 정규화를 사용해 Windows 행 끝만 다른 파일을 실제 소스 수정으로 오인하지 않는다.
- Ruling: 계정의 현재 릴리스는 0.6.0이고 설치 캐시 0.5.1과 구분한다. 파일 목록을 모두 읽어 폐기된 소유 파일만 제거한다. 호스트 생성 manifest와 관련 없는 파일은 보존한다.

## 진행 기록

- 새 검사 파일이 실행기 모듈/업로드 기록 함수가 없어 실패하는 것을 먼저 확인했다. 구현 후 관련 검사 18개와 선택 ESLint, staged diff --check 통과.
- 검증한 항목: 원래 비공개 개인 ID 유지, 일치하는 성공 검사 기록, 검증 입력 변경/명령 실패, 미푸시 커밋 거부, patch 증가, 동일 내용 생략, 실패 업로드의 준비 상태 보존, 원격 릴리스 충돌/receipt 불일치, 폐기 파일 부재, ZIP 스트리밍 바이트 검증.
- 작은 임시 Git/ZIP fixture만 사용했다. 실제 GIS/지명/국가/기간 전수 검사, 전체 suite, 새 모델 학습, 네이티브 앱 빌드는 실행하지 않았다.
- 기존 아이콘/규칙 WIP는 별도 해시 목록으로 보존 중이다. AGENTS.md는 새 릴리스 완료 절차 부분만 index에 올렸다.

## 실제 릴리스와 최종 확인

- 구현 커밋 dcc7eb36c35e3bc9e6b150ceab90fbf13688fd76, WASM 입력 연결 보강 f6d1b709a77e556a372e802178869afdc361ff76, 실제 계정 tar.gz 검증/실패 기록 처리 8177b69e5d5d3f96cff65fdd9ed347e601be160e를 보존했다. 원격 기존 변경과 통합한 최종 work/ui 커밋은 d050a611e442a6edfbb22a2dfcab63e3dc37d208이며 정상 push했다. main 병합/웹 배포는 이 작업에서 실행하지 않았다.
- 해당 수정 중 다른 채팅의 완료 커밋 f18c09a0가 입력을 바꿨을 때 검증기가 실제로 실패했고, 통과 기록을 발급하지 않았다. 사용자의 명시적 조율 승인 후 지도 그리기 플러그인 채팅이 업로드를 보류했다. 그 채팅의 완료 소스/0.6.1 메타데이터 7a3d2ebc와 검증된 P2 WASM을 포함한 647ff0fb0e5b553864cf23d77559fe30e5a9fb7a에서 배포 입력을 검증했다.
- source/WASM 대응은 shared source 635b76eea3c0a3d82662e18da57241b43f369359991bec28dc304d1c0ce8c452, WASM 10b91dc48c96e0477ecddc29cbc63f88532fd6259d08ad5420596fc347e219ae다. 기존 파생물을 사용했으며 이 작업에서는 C++/WASM/네이티브 재빌드를 하지 않았다.
- 기존 PRIVATE USER Map Toolkit을 0.6.0→0.6.1로 갱신했다. ID/개인 범위/비공개 상태는 유지했다. 정확한 계정 ID와 릴리스 ID는 사용자 로컬 Codex 설정에만 보관하며 이 공개 보고서에 적지 않는다.
- 배포된 runtime 코드 식별은 647ff0fb0e5b553864cf23d77559fe30e5a9fb7a, 분석 자료는 8d668a6c9ffb7844849fb63af5b02ebc8a496b70, 기존 모델 해시는 04ee59b043d1fde4a4c407fc079bdb03ba051eceb8adfb4784e7e67c62f7b39c다. 모델/언어팩을 새로 학습하거나 승격하지 않았다.
- 배포 내용 해시 b31fba332fcc6b3a30a43609d08da1a462aa4723adf4802468275e2d929c0193. 배포 검증 기록 SHA-256은 0ce497d7dfa804ad2c920f96b313caceb86563a6eef54067056b08683884cb5c이며 release.json에 포함했다.
- 전송 ZIP은 24,005,594바이트, SHA-256 17316d336f9bdcdc3436f28fd24c85bb478394cd70090be626ecf9c2361600c4, payload는 211개 파일/30,855,668논리 바이트였다.
- 원격 목록 211개를 전부 재조회했고 root/compatibility manifest, release.json, 변경된 지침/수정 계약/C++ 소스를 읽었다. 호스트가 반환한 정확한 새 릴리스 archive는 tar.gz 23,932,240바이트였다. 기존 Windows tar -xO를 사용해 파일을 디스크에 풀지 않고 211개 파일을 모두 비교했다. 두 manifest는 준비한 전체 JSON 설정과 의미상 동일하며, 나머지는 크기/SHA-256이 일치했다.
- 원격 확인 상태는 verified다. 공개 범위를 바꾸거나 새 플러그인을 만들지 않았다. 실제 새 Work 세션의 지도 분석 기능/기기 검증을 이 계정 바이트 검증으로 대체 주장하지 않는다. 기존 채팅/설치 캐시 자동 교체나 앱 재시작도 수행하지 않았다.

## 최종 집중 검사 및 반복 실행

- 21개 관련 검사 통과: map-plugin-release.test.mjs, map-plugin-package.test.mjs, map-cloud-probe.test.mjs. 선택한 producer/release 실행기/회귀 검사 파일 ESLint 통과. 변경 diff --check 통과.
- 실제 배포 준비 시에는 해당 source commit의 검사 19개와 lint를 입력 해시에 연결했다. 이후 실제 서버 tar.gz 및 이전 성공 기록 무효화 회귀를 추가해 최종 d050a611에서 21개와 lint를 다시 실행했다. 두 단계의 검사 exitCode는 모두 0이다.
- 최종 검사 출력 SHA-256: tests 521f7a7c6cd0ba058c19b4e710e66a198cf253ba2d105d2b6653a83c6145ccd0, lint e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855. 최종 커밋에서도 배포 내용 해시는 b31fba33과 같다.
- d050a611을 푸시한 뒤 같은 계정 릴리스를 대상으로 prepare를 다시 실행했다. 결과는 unchanged였고 추가 패키징/업로드/버전 증가가 없었다. ZIP의 크기/해시도 그대로였으며 계정 버전은 0.6.1을 유지했다. 따라서 runtime의 source 표기가 647ff0fb이고 완료 절차 구현의 최종 source가 d050a611인 것은 같은 배포 내용에 중복 릴리스를 만들지 않는 정상 결과다.
- 독립 검토에서 지적한 두 P2(확인되지 않은 receipt만 보고 unchanged 처리, manifest 이름/버전만 확인)는 회귀 실패를 먼저 확인하고 수정했다. unchanged는 정확한 현재 릴리스의 바이트 검증 기록과 연결한다. 원격 manifest와 archive 안 manifest 모두 전체 준비 계약을 확인한다. 실패한 verify 호출은 예전 성공 기록을 활성 상태로 남기지 않는다.
- 초기 기록한 WIP 80개 중 AGENTS.md의 새 완료 절차 부분만 이 작업으로 바뀌었다. 나머지 79개는 바이트 해시가 모두 일치했다. AGENTS의 기존 미커밋 규칙 수정은 그대로 미커밋이며 diff 23+/6-가 유지됐다. 추가된 WASM 두 파일 수정은 다른 채팅이 검증된 P2 대응물을 현재 작업공간에 반영한 것이다. 이를 덮어쓰지 않았다.

## 출력 정리와 디스크

- package 후보는 고정 C 임시 경로 한 벌만 만들었다. 실행환경/전체 저장소/전체 GIS 자료를 복제하지 않았고, 원격 archive도 한 번만 받아 메모리에서 읽었다.
- 사용이 끝난 C:/Users/taeeu/AppData/Local/Temp/pando-map-toolkit-release는 214개 파일/78,842,250논리 바이트다. 후보 payload, 업로드 ZIP, 원격 tar.gz, 임시 업로드 상태를 포함한다.
- D:/dev/worktrees/ui/.library-data/plugin-release는 13개 파일/203,051논리 바이트다. 검사/원격 목록/계획/확인용 JSON과 로그이며 용도가 끝났다.
- 위 두 대상의 절대경로/포함 관계/링크 부재를 확인하고 실행 중 release Node 프로세스가 없는 것을 확인했다. 삭제 명령은 실행 전 자동 승인 검토에서 blocked by policy로 거절됐다. 상세 사유는 제공되지 않았으며 다른 도구로 우회하거나 재시도하지 않았다. 논리 삭제 0바이트, 차단 잔량 79,045,301바이트(약75.4MiB)다. 재시도 후보를 여러 벌 누적하지 않았다.
- 삭제 직전 관측 여유는 C 45,738,840,064바이트, D 57,310,601,216바이트다. 삭제가 실행되지 않았으므로 이를 회수량으로 계산하지 않는다. 동시 다른 작업의 사용량도 이 작업의 단독 증감으로 단정하지 않는다.
- 사용자 로컬 Codex 설정의 작은 target/현재 검증 릴리스 식별은 후속 자동 갱신의 현재 소비자이므로 유지한다. 원본 지도/보고서/기존 모델/활성 환경/아이콘 WIP와 다른 작업의 출력은 이 정리 대상이 아니다.

이 단일 보고서 파일만 라이브러리 publish/check하며 다른 채팅의 미완료 보고서나 모델을 공개하지 않는다.
