## 적용 범위

국가와 강·호수에 `ObjectRef(domain,id)` + lifetime + 공통 geometryBindings(schema 3)를 적용했다. C++ 검증·기간 해석·편집·Undo/Redo·저장, 현재 JS 호출자·코덱·합성 fixtures를 함께 갱신했다. 수계 전용 날짜 선택기는 만들지 않았다. 물 객체의 행정 부모·국기 등록은 거부한다. 상세 수정 파일은 changed-code-files.txt 참조.

형상별 `rendering`이 하천 폭·선 조각별 정점 폭·정렬·연결 정보를 소유한다. 좌표 교체 후 이전 정점 폭과 연결은 제거한다. 공통 명령의 개별/일괄 삭제와 라이브러리 가져오기에 물 객체를 연결했다. 기본 타일·배율 로딩은 유지하며 날짜 변경만으로 전체 수계를 다운로드하지 않는다. 같은 GeometryRef와 준비 입력은 기존 자원 정책으로 재사용한다.

## 카스피해

복원 선택은 **1922-12-30~1925-05-12 양 끝 포함**이다. 그 전후의 현대 기준선 선택 범위는 이어진다. 복원본은 1922년 전후 지도학적 근사, 현대 비교는 Natural Earth 5.1.1이다. 새로운 역사 정확성이나 2026년 실측을 주장하지 않는다.

기존 기본 수계 정본·코어 메타데이터의 카스피해 명칭 대상 조회에서 선행 호수 객체 ID가 발견되지 않았다. `waterbody:caspian`을 안정 객체로 등록하고 `caspian-near1922-approved`는 승인 복원 버전 식별자로 보존했다. 기존 배경 날짜 분기를 제거하고 공통 선택 결과가 객체·수역 채움·육지 마스크를 함께 결정한다. 편집 복사본은 현재 형상으로 국소 육지 마스크를 파생하며 일반 편집 수계가 채움을 소유한다. 국가 영토에서 물을 차감하지 않는다.

## 실제 확인

- 작은 합성 국가/강/호수: 같은 문자열 ID의 도메인 분리, 포괄 경계 날짜, 중복 거부, 물의 행정 부모 거부, 형상 선택·편집·복사·개별/일괄 삭제, Undo/Redo, 전체 형상 저장 왕복, 라이브러리 공통 batch/임시 편집, 형상별 폭·연결과 자원 준비 의존성을 확인했다.
- 관련 기존 합성 기간/저장 회귀를 실행했다. 과거 fixtures·테스트가 이전 API를 사용해 발생한 실패를 현재 계약으로 수정했다. 최종 파일별 결과는 압축 로그에 있다. 전체 테스트 통과라는 주장은 하지 않는다.
- 공통 native API의 물 라이브러리 수용·삭제·Undo/Redo는 작은 C++ 테스트 하나를 WASM으로 컴파일해 실행했다. 두 실패를 재현하고 수정 후 성공했다. Windows 앱 실행파일은 빌드하지 않았다.
- 실제 카스피해: 1922-12-29, 1922-12-30, 1925-05-12, 1925-05-13에 객체와 육지/수역 asset 해시가 일치했다. 동일 복원 형상 기간과 현대 재진입에서 추가 다운로드가 없었다. 테스트 로더의 총 네 요청은 현대 육지/수역과 복원 육지/수역이다. 실제 네트워크 성능 개선율은 측정하지 않았다.
- 후보 Web/앱 웹셸: 1922-11, 1922-12, 1925-04, 1925-05에서 현대→복원→현대 선택과 카스피해 캐시 ID 1개를 각각 확인했다. 해당 관찰에서는 page error/실패 HTTP 응답이 없었다.
- 추가 확대 관찰에서 Web은 오류 없이 완료했다. 앱은 카스피해 형상/마스크가 일치했으나 **올란드(Åland) territorial fill의 PL-MESH-NOT-PREPARED 1건**이 발생했다. 원인·기존 버전 재현 여부는 미확인이다. 이를 전체 화면 검증 통과로 표시하지 않고 별도 미해결 항목으로 둔다.
- 변경 JS/도구의 범위 제한 lint와 diff 확인은 성공했다. 필요한 WASM만 빌드·패키징했다. 전체 검사·벤치마크·실행파일/설치 패키지·GIS 전체 재생성은 실행하지 않았다.

## 판단과 보존

- UI 월말 커서는 유지하고 같은 C++ 해석기에 정확한 일자 조회를 추가했다. 잘못 적용하면 일부 호출자가 월/일 커서 지원 범위를 다르게 기대할 수 있다.
- 선행 호수 객체가 확인되지 않아 새 안정 카스피해 ID를 등록했다. 선행 ID가 별도로 발견되면 출처 정체성의 연결 검토가 필요하다.
- 형상 공백은 기존 공통 규칙대로 비활성으로 해석하며 현대 형상을 자동 대입하지 않는다. 사용자가 공백 자체의 일괄 거부를 기대했다면 추가 정책 선택이 필요하다.
- 올란드 오류는 수계 작업에서 범위를 넓혀 수정하지 않았다. 수계 변경과 연관된 것으로 확인되면 화면 준비 수정이 추가로 필요하다.

execution-evidence.zip에는 최초 실패·수정 후 결과·실행 도구·화면·ledger 원문을 압축 보존했다. 모든 ZIP 항목은 압축 전후 SHA-256을 대조했다. 중복 SDK 다운로드 파일은 없었다. SDK 1970577553 bytes, CMake/Ninja 84851345 bytes와 고정 WASM 증분 빌드(확인 시 29159600 bytes)는 다음 공통 C++ 수정/자료 통합의 현재 빌드 소비자가 있어 유지한다. 실제 드라이브 여유 변화는 동시 작업도 포함하므로 삭제 절감량으로 해석하지 않는다.

임시 정리 결과: 자동 승인 검토가 삭제 스크립트 전체를 실행 전에 `blocked by policy`로 거부했다. 삭제 대상/논리 바이트는 성공 0이며, 다른 도구로 우회하지 않았다. 확인 시 임시 작업 파일 3829952 bytes와 종료된 합성 테스트 실행 산출물 2393289 bytes를 유지한다(cleanup.json). 보고서 압축 보관본은 원격 바이트 확인을 마쳤다. 삭제에 따른 실제 드라이브 증가량은 주장하지 않는다. SDK·증분 빌드는 계속 사용하는 의존성이다.
