## 구현

- 지형의 데이터·그래픽 컨텍스트 수명과 프로젝트 세대를 분리했다. 국가 취소 scope와 지형 업로드 scope를 분리하고 지형 작업에서 문서 세대 태그도 제거했다. 같은 자료를 다시 열면 다운로드·텍스처를 유지한다.
- 현재 화면 목표 타일을 우선 요청한다. 화면 밖 세계 예비 타일이 현재 화면 준비 완료를 막지 않는다. 예비·인접 요청은 후순위다.
- CSS scale 504 초과에서는 부족한 목표 해상도를 낮은 해상도 타일로 확대하지 않는다. 실패·대기에는 단색 바탕을 사용한다. 국경·육지 연동 배율 정책은 유지했다.
- 초기/프로젝트 교체에서 지형·색채·실제 물리 육지 리소스가 함께 그려진 프레임을 인정한 뒤 국가를 공개한다. 빈 육지 목록과 빈 완료 키는 완료가 아니다. 첫 국가 프레임 후 일반 이동에서는 국가를 반복해서 숨기지 않는다.
- 새 Core 문서 승인 후, 메시를 계산하는 동안 새 배경을 그릴 수 있도록 기존 재계산 진입점에서 표시 차단을 해제한다. 보기 복원/초기 범위 설정은 메시 계산 전에 수행한다.
- 완료된 mesh Worker와 원본 형상 hash/알고리즘 캐시를 유지한다. 바쁜 이전 계산의 취소는 유지한다.
- 공간 블록 생성은 전체 반복 sort를 결정적 중앙 분할로 바꿨다. 좌표·감김 순서·삼각형 집합·국가 범위·블록 크기는 유지한다.
- 메시 Worker 입력은 원본 좌표를 분리하지 않는 Float64 전송용 복사본으로 포장한다. 8192점마다 작업을 양보한다. 좌표 배열의 메시지 간 구조 복제를 줄였다.
- 국가 라벨의 Worker/복구 계산을 국가 공개 뒤로 미루고 기존 동일 형상 요청 중복 억제를 유지했다. 라벨 큐 자체나 별도 상태 관리자는 추가하지 않았다.
- Canvas Worker는 프로젝트 교체 시 유지한다. 새 세대에서 이전 국가/수역 편집과 revision은 버리고 늦은 응답을 거부한다. Canvas2D도 목표 해상도와 표시·완료 판정을 공유하며 atlas 다운로드는 single-flight다.

## 집중 검증

- 관련 단위 84/84 통과: 실제 지형 owner, 업로드 취소, 실패, 이동 우선순위, 캐시 재사용, 메시 포장 취소/정밀도, Canvas 전송 세대, 공간 분할 원시값/감김/소유권 보존.
- 변경 소스 린트 및 생성 메타데이터 검사 통과. 전체 검사, C++ 빌드, GIS 생성/검증, main 통합, 푸시, 배포, 설치 패키징은 하지 않았다.
- Web 고배율 첫 진입에서 모든 지형 타일/색채 요청을 지연했다. 국가 메시 준비 후에도 국가는 숨김, 낮은 해상도 tile draw 없음. 지연 해제 후 배경 완료 시각 26767ms, 국가 공개 26818ms 순서 확인. 이 시각은 지연을 주입한 값이므로 성능 수치가 아니다.
- 동일 Web 세션에서 같은 자료를 다시 열어 mesh 207/207 재사용, 지형 업로드 26회에서 증가 없음 확인.
- 실제 브라우저 WebGL2 고배율 pending→정밀, Canvas pending→정밀 및 저배율 복귀 각각 통과.
- 첫 회귀 검사에는 숨겨진 메뉴 항목을 바로 누른 테스트 오류가 있어 메뉴 열기 동작을 추가했다. Canvas 검사도 실제 프레임 공개 완료 전에 줌을 바꾸던 경쟁을 고쳐 실제 공개를 기다린 뒤 검사한다. 이 수정 이후 각각 통과했다.

## 측정과 한계

같은 PC 브라우저의 단회 관측이며, 반복 통계나 고정 시간 보장은 아니다. 공개 배포본 기준선의 메시 13284.8ms / 삼각분할 8949.5ms / 공간 블록 2479.5ms와 비교해 로컬 관측은 메시 10890.1ms / 삼각분할 8701.9ms / 공간 블록 953.1ms였다. 초기 물리 배경은 렌더러 시작 후 약 6498.6ms, 국가 확인은 navigation 기준 약 18690.7ms였다. 기준선은 국가가 지형보다 먼저 그려졌고, 수정 후에는 배경부터 확인됐다. 로컬 관측의 장기 메인 작업은 12회, 최대 630ms, 합계 2661ms여서 긴 작업이 완전히 제거된 것은 아니다.

지연 회귀 시나리오에서 최초 메시 계산은 16355.1ms(삼각분할 13194.9ms), 캐시 재진입은 2823.9ms(삼각분할 0ms, 207개 재사용)였다. 동시 앱 실행 등 부하와 조건이 달라 첫 로컬 관측과 직접 속도 비율로 합치지 않는다. 캐시는 메시 조립·stroke·공간 블록 재생성 비용까지 없애지는 않는다.

실제 Windows WebView 개발 앱을 실행해 기존 지도와 준비 완료 상태를 관찰했다. 이후 개발 리로드에서 /__shell/health가 'Library storage is already running in another worktree; retry after it finishes.'를 보고했고 갱신 자산을 승인하지 못했다. 외부 UI 입력도 감지되어 자동 조작을 중단했다. 최신 코드의 실제 WebView 고배율 첫 진입·재진입 전체 검증은 미완료다. 브라우저의 App 경로 검사를 실제 WebView 완료로 간주하지 않는다. 다른 작업의 서버·라이브러리 lock·앱을 종료하거나 제거하지 않았다.

독립 최종 코드 검토에서 Canvas 요청 controller 누락, 빈 육지 준비 인정, Canvas2D 중복 다운로드/완료 판정, 이전 수역 편집 잔존을 확인했고 모두 수정했다. 검토자가 전체 검사나 코드 수정을 수행하지는 않았다.
