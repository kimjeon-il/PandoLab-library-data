## 원인과 실제 재현

이전 수정은 지형 타일 준비 경로의 배율 제한을 제거했지만, 실제 그리기 경로에 객체 표시 완료 여부와 연결된 조건을 남겼다. 이전 확대·축소 검증도 객체 로딩 완료 후에만 시작해서 이 구간을 놓쳤다.

WebGL의 `terrainVisible`은 물리 육지 마스크가 준비되어 있어도 `countriesPublishedGeneration === projectGeneration || terrainReady`가 거짓이면 꺼졌다. 객체가 표시되기 전 새 해상도 타일을 요청하면 `terrainReady=false`가 되어 기존 유효 타일까지 숨긴다. 객체 표시가 완료되면 앞 조건이 참으로 고정되어 같은 상황에서 깜빡임이 없어진다. Canvas의 `backgroundPending` 및 `hold`도 같은 연결이었다.

공개 웹을 별도 Edge/D3D11 컨텍스트에서 실행하고, 프로젝트 배경 렌더링이 허용된 뒤 국가 mesh 준비만 지연했다. 배율 1의 지형을 준비한 다음 LOD 3 응답은 계속 지연했다. 사용자 탭은 새로고침하거나 조작하지 않았다.

고배율 전후 프로젝트 세대는 1, 물리 마스크 키는 `physical-land`로 같았고 기존 LOD 0/1/2 타일 목록도 동일했다. 흑해 픽셀도 지형의 69,119,159 대신 평면 바탕 106,168,210으로 바뀌었다. 형상 소실이 아니라 지형 표현을 그리지 않는 문제였다.

응답 코드에서 WebGL의 해당 조건만 제거한 A/B 실험에서는 객체 표시 세대 -1, LOD 3 준비 0/22, `terrainReady=false` 상태에서도 지형을 그렸고 색이 유지됐다. 원본 및 A/B 결과는 각각 `startup-zoom-result.json`, `startup-zoom-result-ungated.json`에 보존했다. `startup-zoom-probe.mjs`가 재현 도구이며 앞뒤 화면은 `startup-before-objects-high*.png`이다.

## 수정 범위

- WebGL 지형 그리기에서 국가 표시 세대·목표 해상도 완료에 의한 전체 숨김 조건을 제거했다.
- Canvas에서 같은 숨김 조건과 폐기한 `backgroundPending` 메시지 생산·소비를 제거했다.
- 유효한 현재 프로젝트의 준비된 타일을 계속 사용한다. 일부 타일이 보이더라도 빠진 목표 타일·DEM·tint가 있으면 준비 완료로 인정하지 않는다.
- `recordMapPresentation`, 최초 선명한 배경과 국가 표시 순서, 프로젝트/컨텍스트 세대 검사, 캐시 보호·실패·재시도 코드는 바꾸지 않았다.
- 준비된 개별 타일의 점진적 표시와 준비 완료 판정을 구분하도록 관련 Canvas 테스트를 갱신했다. 불완전한 타일 집합은 준비 완료가 아니다.

## 실제 실행한 집중 확인

- 관련 단위 테스트 3개 파일 39개 통과: `canvas-terrain-independence`, `gpu-terrain-preparation`, `gpu-base-scene-order`. 출력의 HTTP 503·잘못된 DEM 진단은 의도한 실패 fixture에서 발생했다.
- WebGL 신규 startup 회귀 테스트는 수정 전 새 LOD 3 타일 0개, 유효한 이전 LOD 존재 상태에서 실제 terrain draw가 없어 실패했다. 이후 같은 검사 통과.
- 웹 브라우저 6개 통과: 최초 배경/국가 표시 및 재열기, WebGL 기존 overview/detail/객체 로딩 전 확대·축소, Canvas 객체 로딩 완료/로딩 전 확대·축소. 준비 중 타일 범위와 실제 픽셀을 확인했다.
- 검토에서 확대 직전 프레임이 픽셀 검사를 통과시킬 가능성을 찾아 보강했다. 타일 준비 직후의 목표 LOD를 draw마다 기록하고 `targetLevel > fallbackLevel`인 실제 draw만 인정한다. 보강 후 WebGL 3개 재통과.
- 앱 웹셸 2개 통과: 기본 앱의 지형 메뉴·요청 부재와 프로젝트 상태 보존, 휴대전화 Canvas 초기 실행. 네이티브 EXE/APK 검증은 실행하지 않았다.
- 보강한 WebGL 3개와 앱 2개 결과: `startup-focused-browser.json` (expected 5, unexpected 0, skipped 0, flaky 0).
- 독립 코드 검토: 제품 코드 결함 지적 없음. 픽셀 검사의 이전 프레임 문제는 보강 후 재검토에서 해결 확인.
- `git diff --check` 통과. 전체 검사·GIS 재생성·네이티브 빌드·설치 패키지·대형 자료 복사는 실행하지 않았다.

4173 포트는 다른 작업의 Viewer 전용 개발 서버여서 앱 주소가 404였다. 이를 제품 실패로 처리하지 않았다. 해당 서버를 종료하지 않고 기존 테스트 서버의 설정 가능한 포트 4174를 한 번 사용해 메모리 snapshot으로 확인했다. 검증 서버는 종료됐다.

## 저장공간과 남은 단계

기존 상설 UI 작업트리와 자료 캐시를 재사용했다. 완료 시 D드라이브 여유는 60,918,050,816바이트였다. 다른 작업도 같은 드라이브를 사용하므로 여유 공간 변화는 이 작업이 회수한 용량으로 주장하지 않는다. 증거 PNG·재현 스크립트·결과 JSON은 이번 전후 비교를 위한 외부 보고서 증거이며 실행파일·지도 복사본을 만들지 않았다.

자동 승인 검토가 `test-results`의 PNG를 보존본과 비교해 정리하는 PowerShell 명령을 실행 전 `blocked by policy`로 차단했다. 우회 도구로 같은 삭제를 시도하지 않았다. 따라서 삭제 성공은 0바이트이고 검증 잔여물 2,516,649바이트(약 2.40MiB)가 남았다: PNG 934,706 / 825,333 / 756,565바이트와 `.last-run.json` 45바이트. 이 파일들은 제품 실행에 필요해서 보존한 것이 아니라 정리가 차단된 항목이다.

이번 수정은 로컬 작업 커밋까지다. 공개 웹은 수정 전 main을 계속 사용한다. 보고서는 새 `startup-*` 파일만 범위를 지정해 보관·푸시·원격 바이트 확인한다. 기존 보고서의 다른 판본·다른 작업의 미게시 편집본은 포함하지 않는다.
