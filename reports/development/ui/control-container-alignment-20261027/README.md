# 아이콘 버튼과 부모 배치 규칙 조사

> 보고서 ID: UI-CONTAINER-20261027 · 상태: investigated · 제품 반영: not-applied · 색인일: 2026-10-27
> 조사 기준: Web/App 공통 소스 `255b952a2a9c36fd0686bacf9e1c8bf709c19eb8`
> 원본: Pando `work/ui`, 아래 재현 도우미와 측정 파일

## 대상과 방법

모바일 검색 아이콘처럼 부모 칸은 일반 입력 48px, 내부 아이콘 버튼은 40px를 사용하면서 정렬 또는 크기가 어긋나는 경우를 조사했다. 현재 CSS 색인에서 일반 컨트롤 높이를 크기·flex·열 정의에 사용하는 53개 규칙을 추렸다. 53건은 오류 수가 아니다.

원본 CSS와 실제 클래스·부모 구조를 사용한 7종 배치 표본을 IAB에서 렌더링했다. 실제 프로젝트 상태나 실제 WebView 실행으로 간주하지 않는다. 표본용 위치 규칙은 일부 제품 위치 규칙에 덮이므로 페이지 내 절대 위치와 잘림은 판정 대상에서 제외했다. 버튼 크기, 부모와의 상대 위치, SVG 박스를 확인했다. 전체 테스트·C++ 빌드·GIS 검증은 실행하지 않았다.

표본 뷰포트 설정은 390×844, 844×390, 320×700, 1440×900이다. 스크롤바를 제외한 실제 문서 너비는 각각 375, 829, 305, 1425px이며 `measurements.json`에 기록했다. 다섯 측정은 editor mobile, viewer phone-landscape, editor phone-landscape, viewer mobile, viewer wide 순서다.

이번 확인 범위에서 검색 외에 확정한 같은 계열의 추가 결함은 지도 도구의 가로 flex 크기다. 모든 화면과 동적 상태가 무결하다는 전수 보증은 아니다.

## 수정 방향과 한계

검색의 닫힌 슬롯과 지도 도구의 아이콘 flex 폭은 아이콘 규격을 따르게 하고, 펼친 검색 입력은 일반 입력 높이를 유지하는 것이 맞다. SVG에 개별 이동 보정을 넣을 문제는 아니다. 분포 행은 담당 행의 배치 선언과 아이콘 열 토큰을 함께 정리해야 한다. 제품 소스는 이번 조사에서 수정하지 않았다.

실제 앱 WebView, 전체 프로젝트 동작, 터치 및 팝업 전환은 이번 범위에서 실행하지 않았다. 추가 결함은 현재 소스의 배치 표본 재현 근거이며 실제 앱 화면 재현 완료로 표현하지 않는다.
