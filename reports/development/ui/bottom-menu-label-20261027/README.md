# 하단 도구막대 메뉴 통합과 메뉴 이름 표시

> 보고서 ID: UI-BOTTOM-MENU-20261027 · 상태: locally-implemented · 공개 반영: not-applied · 색인일: 2026-10-27
> 코드 기준: work/ui `5e44c873d227c3b5683eca2fe71ae37692ab8304` 위의 미커밋 UI 변경
> 원본: 편집기 템플릿, 기존 mobile sheet/workspace 소유자 및 공통 CSS

## 변경 내용

기존 우측 사이드바 구현을 보존하고, 하단 도구막대가 나타나는 편집기 화면에 메뉴를 여섯 번째 칸으로 통합했다. 메뉴 DOM·ID·이벤트는 하나이며 CSS 배치만 화면 모드에 맞춘다. 가로에서는 메뉴가 사이드바 상단에 고정되고 아래 목록만 스크롤한다. 두 모드 모두 아이콘 아래에 메뉴 이름을 표시하며, 메뉴는 아이콘 전용이 아닌 공통 내비게이션 버튼 규칙을 사용한다.

하단 6칸은 균등 폭이며 14px 글자를 줄이지 않고 줄바꿈한다. 기존 workspace 소유자가 ResizeObserver로 통합 도구막대 높이를 측정해 시트와 지도 여백에 전달한다. 관찰 대상의 높이는 이 측정값에 의존하지 않는다. 화면 모드를 벗어나면 측정값을 해제하고 dispose 시 observer를 해제한다. 별도 상태 관리자·프로젝트 형식·공개 API는 추가하지 않았다.

메뉴·파일 메뉴는 하단 막대 위에 오른쪽 정렬되며, 가로에서는 사이드바 왼쪽에 열린다. 기존 상단 떠 있는 메뉴 배치는 viewer 제품에만 남겼다. 파일 메뉴의 상단 알림 오프셋은 편집기에서는 해제하며 웹의 기존 동작은 유지한다. 키보드의 visual viewport 높이와 오프셋도 기존 workspace 표시 정보에서 계산해 도구막대·메뉴·시트·지도 여백에 반영한다.

## 실행한 검증

관련 브라우저 시나리오 총9개가 통과했다. 전체 테스트·C++ 빌드·GIS 검증·설치 패키징은 실행하지 않았다.

- button-consistency 중 가로 도구막대 폭·200% 글자 확대와 스크롤 중 메뉴 고정, 메뉴/다른 버튼의 일반·호버·선택·선택+호버 스타일 일치, 320px 공통 글자 규격: 3건.
- phone-landscape-surface-contract 640×360·844×390: 2건. 상단24px·우측12px의 CSS 안전 영역 모의도 포함한다.
- workspace-surfaces의 새 하단 메뉴 시나리오: 1건. 320·390px 및 100·200% 글자 크기, 6칸 균등 폭·높이, 줄바꿈/잘림 없음, 실제 측정 높이와 시트 경계 오차1px 이내, 메뉴→파일→뒤로→Esc 포커스 복귀, 키보드 높이450px 모의와 입력 보존, pageerror 없음.
- phone-landscape-editor: 1건. 메뉴 이름이 SVG 아래에 위치함을 명시적으로 확인하고 메뉴 전환·키보드·회전·초안·Undo/Redo·지도 위치 보존을 확인했다.
- viewer-search-responsive 640·844px: 2건. 기존 웹 검색·선택·회전 동작과 앱 데이터 분리를 확인했다.
- 최종 높이/문구 검증을 추가한 실제 편집기2건 재실행: 통과(각17.8초·17.5초).
- 관련 JS와 브라우저 검사 ESLint 통과. 공통 UI spacing/component 검사 통과(1846규칙, 28 primitives, 140버튼). 변경 패치 공백 검사 통과.

중간 하단 시트 경계 검사는 fractional 높이를 올림하여 예약한 차이1px 때문에 실패했고, 겹침 방지를 유지하면서 설계의1 CSS px 기준으로 측정하도록 수정했다. 파일/API 동작이나 실제 결과를 무시해 기대값을 바꾼 것은 아니다. 마지막 읽기 전용 코드 리뷰에서는 추가 제품 결함이 발견되지 않았다.

## 화면과 미검증 환경

첨부는 실제 앱 프런트엔드를 Chromium에서 실행한 화면이다. `bottom-menu-320.png`에서 하단 메뉴와 검색 시트의 경계를, `landscape-menu.png`에서 우측 메뉴 이름과 편집 패널을 확인할 수 있다.

Windows 실제 WebView 실행은 현재 다른 작업의 native/build 입력 미커밋 변경 때문에 기존 개발 실행물 검증 단계에서 중단됐다. 이 작업에서는 해당 변경을 커밋·푸시하거나 네이티브 빌드로 대체하지 않았다. 이번 변경의 실제 Windows WebView 및 Android 기기·시스템바·물리 터치는 미검증이다. 브라우저의 모의 키보드·안전 영역 검증과 구분한다.

## 반영 범위와 보관

로컬 work/ui 구현·집중 검증까지만 진행했다. main 병합·앱 Git 푸시·배포·앱 실행 파일 갱신은 하지 않았다. 기존 우측 사이드바 작업과 다른 채팅의 native/아이콘/CI 미완료 변경을 보존했다.
