객체 호버의 깃발 누락, 하위 객체 경계, 웹 조립부의 독자 규칙을 재점검했다. 상설 `work/ui`의 별도 프로젝트 설정·시점 비교·Core/WASM 작업은 보존하고 배포에서 제외한다. GIS 원본·형상·역사 자료는 수정하지 않았다.
`viewer-map`, `viewer-composition`의 조회·가시성·색상·라벨·투영·입력·렌더 자원 연결을 앱 조립부 및 실제 피호출 소유자와 대조했다. 색상 상속·경계 위상·분포·일반 객체·수계·라벨 배치·카메라·품질 계산은 기존 공통 소유자를 사용한다. 테마나 상태를 전달하는 포트 바인딩은 남지만 새 정책 구현을 만들지 않았다.
웹 표시 변경은 세션의 열람 상태를 바꾸고 앱은 문서 명령을 실행한다. 편집 도구·초안·이력·저장·자동저장 등록, HTML 출력과 배포 목록은 제품 역할에 따라 다르다.
초기 preview 선택은 웹의 저장 문서 기반 시작과 앱의 내장 preview 시작 사이에 차이가 남는다. 앱도 저장 프로젝트를 시작할 때는 preview를 사용하지 않는다. 이 경로는 이번에 변경하지 않았고 전체 시작 시간·메모리·성능이 같다고 주장하지 않는다. 저장소 전체 모든 동작의 동등성 증명으로도 확대하지 않는다.
- 현재 Core/WASM writer로 부모·자식·독립 영토·독립 권역, 직접 지정 깃발, 분포, 일반 선 객체가 있는 GPKG를 만들고 두 제품의 실제 파일 메뉴로 열었다.
- 실제 공통 렌더러의 geometry/style/order 패킷과 외곽선을 비교했다. 알고리즘을 테스트에 복사하지 않았다. 부모·자식의 실제 지도 포인터 호버와 깃발, 호버 전후 문서 불변도 검사한다.
- 깃발 누락, 표시 여부 함수 부재, `Polygon`/`MultiLineString` 차이, Worker 완료 후 갱신 누락은 수정 전 실패를 확인했다. 합성 형상·비정규 UUID·분포와 겹친 포인터 지점의 테스트 준비 오류는 제품 결함으로 집계하지 않았다.
