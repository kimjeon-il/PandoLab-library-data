## 대상과 자료

사용자 승인에 따라 현재 대표 형상의 FRA/MCO 육상 국경, 모나코 해안 전체 및 프랑스 측 필수 접합부를 교정했다. 국가 ID·존속기간·버전 ID·부모·이름·과거 형상은 유지했다. 프랑스의 이전 안도라 교정 및 다른 국경 보충 기록도 보존했다.

- 육상: 미국 국무부 LSIB 11.4, 발행 2025-02-24. 원본 선 260점과 원본 master 해시를 보존했다. https://geodata.state.gov/geonetwork/srv/api/records/3bdb81a0-c1b9-439a-a0b1-85dac30c59b2
- 해안: IGN BD TOPO v3 WFS의 `limite_terre_mer`, 만조선 `Plus hautes eaux`. Monaco `TRONLAIS0000002478911964`, 서쪽 `TRONLAIS0000002478911965`, 동쪽 `TRONLAIS0000002478912821`. 모나코 해안은 1,795점이다. EPSG:4326 응답을 직접 사용했다. https://www.data.gouv.fr/dataservices/api-geoplateforme-diffusion-dobjets-wfs
- 해안 속성의 확인일 2021-11-01, DB 수정일 2024-09-23, 수집일 2026-10-22를 구분한다. `published: null`이며 수정일을 발행일·측량일로 바꾸지 않았다. 데이터의 FR 국가 코드 속성을 영토 귀속 근거로 쓰지 않았다.
- IGN 라이선스는 Licence Ouverte / Open Licence 2.0이다. 저작자·수집일·접점 수정과 원본 응답 해시를 기록했다. https://www.ign.fr/institut/des-donnees-et-logiciels-ouverts-au-service-de-la-nation
- 육상 비교: IGN `commune`의 Cap-d'Ail·La Turbie·Beausoleil·Roquebrune-Cap-Martin. 탐색 단계에서 끝점을 투영해 추출한 국경 호와 LSIB의 연속 거리 상한 약 0.120 CSS px였다. 이 추출은 정식 양국 승인선 검증이 아니다.

CNIG의 2022년 기록은 양국이 공동 디지털 국경선을 만들었고 2023년 DB 반영 및 후속 승인을 예정했다고 설명한다. 후속 정식 승인 여부는 이번에 확정하지 않았다. https://cnig.gouv.fr/monaco-a25929.html

Mareterra 사업 원문은 해상 구조물 완료를 2019년 12월, 간척지 형성을 2020년, 개장을 2024-12-04로 구분한다. 2024년 개장일을 국경·해안 형성일이나 국가 존속 시작일로 입력하지 않았다. 현재 형상만 교정하며 새 역사 버전은 만들지 않았다. https://mareterra.com/en/ 및 https://mareterra.com/en/news/

## 방법과 확인

기존 모나코 도형은 약 18.839810㎢였고 LSIB 국경과 최대 약 19.96 CSS px 달랐다. 육상선만 바꾸면 해안 접속이 깨지므로, 원본 해안에서 실제 교점을 먼저 찾고 그 안쪽 구간을 교체했다. 프랑스 외측 접점은 서쪽 [7.407500968129213,43.720986946748155], 동쪽 [7.457628188085217,43.75908999380241]이다. 임의 외측 연결선은 만들지 않았다.

모나코 형상은 LSIB 국경과 IGN 해안으로 조립했다. 양 끝 LSIB 좌표를 IGN의 공통 해안 접점으로 맞춘 이동은 각각 0.0275514 / 0.0061082 CSS px다. 일반 국경 교체의 육지 합집합 불변 검사는 유지했다. 이번 대상만 원본 기반 해안 교정 호로 기대 육지 마스크를 만들고, 그 밖의 변경을 거부한다. 잘못 확대된 옛 모나코 대표점의 위치를 보존 조건으로 쓰지 않는다.

실제 C++ 정규화한 두 국가 검토 사본에서 다음을 확인한 뒤 정본에 적용했다. 실제 적용 파일은 검토 사본과 바이트가 같다.

## 검사와 제품 반영

- 관련 Python 파일 최종 19/19 통과. 일반 교체·폐곡선·삼국접점 기존 사례와 해안 공유선·원본 해시·만조선 선택·잘못된 접점·교정 밖 변경 거부·프랑스 섬/구멍·현재 버전 제한·출처를 포함한다. 전체 테스트·린트·벤치마크는 실행하지 않았다.
- 첫 추가 사례는 미구현 함수로 실패했고, 구현 후 Shapely tuple 입력 처리 1건을 수정했다. 최종 독립 읽기 전용 검토 1회에서 접점 조정으로 인위적 외측 교점이 생길 수 있는 Important를 발견했다. 해당 실패를 재현한 뒤 원본에서 교점을 먼저 선택하도록 수정했고 최종 파일이 통과했다. 수정 후 실제 후보는 앞서 C++ 검토한 후보와 바이트가 같았다. 검토자의 테스트·빌드 실행은 없었다.
- 국가 청크 281개·현재 선택 258개·국가 파일 277개/전송 묶음, world mesh/preview/bundle, canonical/preview 공유선, 고정 polygon 메쉬와 메타데이터를 생성했다. 고정 메쉬 324개 중 321개를 재사용했다. 빌드는 `0.36.0-build-fae66fb9988b`, 자료는 `data-b5495cd43ea09bbda19c9a3e689e6918`, worldDataVersion은 `f2cd115ef31fb66c58f81a00f7eaa4bdbbea3914f779c9e50659cb541362cabe`다.
- Web 뷰어 로딩·모나코 검색·이동·확대, 앱 웹셸 검색·선택·상세 확대와 모나코 약 2.1km² 표시를 확인했다. 해당 탭의 오류 로그는 0개다. 스크린샷 viewport는 2560×1440이며 앱 편집 패널이 열린 지도 너비는 2233 CSS px다. 작은 국가의 세부 해안은 이 화면만으로 정밀 판독할 수 없어, 정규화 도형의 확대 비교 그림과 별도 정량 검토를 근거로 남겼다.
- WASM·Windows 실행파일 재빌드, 네이티브 앱 실행, 원격 게시 확인은 하지 않았다.
