## 대상과 기준일

참조 이미지의 오프라인 OCR·독립 지명 검색·정합/경계 검토·공유 원본 저장을 구현한 현재 개발판을 main에 통합하고 기존 Pages viewer를 배포했다. 실제 경계 모델을 학습·승인한 출시가 아니다. 국가 귀속이나 역사적 경계를 수정하지 않았다.

영구 `work/ui`를 재사용했고, 깨끗한 main에 fast-forward로 통합했다. 다른 영구 브랜치·작업물은 이동하거나 삭제하지 않았다. 자료 저장소의 해당 핀을 먼저 게시한 뒤 코드 main을 게시했다.

## 자료 준비와 실제 OCR 후속

기존 `tools/reference-analysis/corpus.py`에 `--prepare-review`를 추가했다. 검증된 acquired JPEG와 provenance를 먼저 모두 확인하고, 원본 복사 없이 기존 schema의 empty `reviewed=false` labels 및 `corpus.draft.json`을 생성한다. header만 읽어 원본 크기를 유지한다. 기존 편집 라벨과 draft를 덮어쓰지 않으며 변경된 source identity/해시/크기와 경로/junction 탈출은 거부한다.

관련 Python 18개가 통과했다. 실제 두 자료에서 생성·재실행과 학습 validator 거부를 확인했다:

- [draft](corpus/corpus.draft.json)
- [페르시아어 원본 좌표 라벨](corpus/labels/loc-tehran-1889-preview.json): 2048×1964, 공식 축소본이라는 provenance 유지.
- [우르두어 원본 좌표 라벨](corpus/labels/zenodo-urdu-punjab-undated.json): 17180×14414, 발행연도·지구 미확정 유지. 8MP 앱 파생본의 좌표로 대체하지 않았다.

## 남은 단계와 한계

1. 7개 겹침 채널과 도시 기호·원어 전사·독립 정합 확인점을 실제 검수한다. 제작 계열/판본/재스캔 그룹과 서로 분리된 train/validation/test를 고정한다. 현재 두 자료만으로는 세 독립 제작 계열과 전체 문자권 평가군이 확보되지 않는다.
2. 검수된 실제 지도 라벨로 학습→독립 평가→ONNX export를 진행한다. 현재 출시 모델은 없고 missing-model gate를 유지한다. 목표 지역 선택률 95%, 경계 precision 95%/recall 85%를 달성했다고 보고하지 않는다.
3. 저신뢰 OSD와 역사 활자·긴 연결 글자·다중 panel의 실제 OCR/위치 추정 품질을 개선한다. 현재 layout/graticule는 보수적인 후보와 명시적 CRS 확인을 사용하며 곡선/사선 격자·미상 datum을 해결하지 못한다.
4. Android 실제 기기의 offline 흐름과 8MP/384MiB/180초 목표를 측정한다. 현재 실제 기기가 연결되지 않았고 대형 원본 crop decode memory도 미검증이다.
5. 독립적인 시대별 경계가 없으므로 역사적 귀속이나 2560 CSS px/0.5 CSS px 정확도 검증을 실행/통과로 보고하지 않는다.

## 저장공간·판본

대형 빌드는 기존 고정 디렉터리·활성 증분 cache만 사용했다. 자료 원본을 복제하거나 보관용 앱 바이너리를 만들지 않았다. 이전 자료 cache 2207af99의 845840586 bytes 제거 기록은 [기존 cleanup 결과](cleanup-result-20261023-105048-538.json)에 있으며 이번 배포에서 다시 회수한 용량으로 합산하지 않는다.

최종 검증 이후 hash가 현재 커밋의 정본과 일치하는 다운로드 CI 중복 JS/WASM 두 파일과
완료한 임시 browser harness 두 파일을 제거했다. 제거 파일 실측 합계 3,123,745 bytes,
D: free 30,291,574,784→30,294,708,224 bytes. [정리 결과](cleanup-release-5de478ba-2026-10-23.json)에
각 절대 경로와 bytes를 기록했다. 재귀 삭제나 활성 cache 삭제는 없었다. 이번 작업에서 띄운
4287번 테스트 서버 PID16440만 포트·명령을 재확인한 뒤 종료했다. 다른 서버/앱은 종료하지 않았다.

자동 정책이 이전 Pages stage 약 204MB 삭제를 거부해 남겨뒀다. 재시도/우회하지 않았다. 광범위 검사 목록 조회도 CHECK-BUDGET hook이 거부했으며, 파일별 관련 검사와 공식 CI 결과만 기록했다. 완료한 native profile 삭제 거부 기록도 유지한다.

이 후속 보고서와 새 annotation/OCR 원문은 현재 b4c115dc의 외부 `.working` 원본에 작성돼 있으며 아직 새 report-only 자료 핀으로 보관하지 않았다. 배포된 main의 자료 핀·runtime pairing을 보고서 저장만을 위해 변경하지 않았다. 기존 보고서·원본은 삭제하거나 성공으로 고쳐 쓰지 않았다.
